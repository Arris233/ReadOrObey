# COCO 数据审计、筛选与 Pilot 决策（2026-11-24）

## 数据现状

- 官方 `val2017.zip` 为 815,585,330 字节，ZIP CRC 全部通过，已解压 5,000 张图；`annotations_trainval2017.zip` 为 252,907,541 字节，使用其中的 `instances_val2017.json`。
- 原始标注包含 5,000 张图、36,781 条实例标注和 80 个细类。官方验证集与许可说明见 [COCO 2017 Detection](https://cocodataset.org/dataset/detection-2017.htm) 和 [COCO Terms of Use](https://cocodataset.org/dataset/termsofuse.htm)。原始图片的版权仍属于各自权利人；团队代码仓库只共享 manifest，不上传原图。
- `audit_stats.json` 是本次机器统计；`candidate_pool.json` 是确定性候选池；`contact_01.jpg`–`contact_05.jpg` 供目视复核；`coco_review.csv` 记录每张候选的决定。`coco_base_120.provisional.json` 是**暂定**的成对实验索引，不能直接作为正式结果的冻结样本。

1,326 张合格图覆盖 61 个细类。候选 200 张也覆盖这 61 类；主体 bbox 占比的五数概括为 0.251 / 0.332 / 0.436 / 0.597 / 0.839。200 张中，83 张只有一个已标注类别，117 张有至少两个；“异类 <12%”只能控制**标注框**的显著性，不能保证肉眼看不到第二个物体。

候选池的超类分布为：animal 40、food 33、vehicle 32、furniture 19、outdoor 16、appliance 14、indoor 13、electronic 9、accessory 8、sports 7、kitchen 5、person 4。这个分布是为覆盖类别而设计，**不是 COCO 原始分布**；正式结果只能解释为在本项目受控样本上的行为，不应当作 COCO 总体准确率。

## 现阶段暂定切分

接触图中已有 17 张明确不合适的样本被标为 `reject`，原因包括原图大字、主体模糊、视觉主体与标注不符及多主体混杂。剩余 183 张仍为 `pending`，尚未完成逐张原尺寸审核。

`prepare_coco_manifest.py` 从候选池中先按 animal / vehicle / food / indoor 各取 3 张作 Pilot，再取 120 张 Formal 和 12 张备选。当前 Formal 有 56 个细类、12 个超类；A/B/C/D 正确答案各 30 张，主体 bbox 占比中位数 0.447，次大异类框占比中位数 0.006。每张图的 C0–C3 必须复用这里的 `image_id`、`options`、`answer` 与 `wrong_class`。

**暂定选项仍需审核**：脚本只排除了 COCO 已标注类别，无法排除图中可见却未标注的类别。尤其是 `wrong_class` 若在原图中真实出现，C2 的“误导”标签就不再是错误标签。要逐张看原图和四个选项，必要时从备用类别重新采样，而不是把样本直接用于正式实验。还要检查语义重叠，例如 `couch/chair`、`cup/bowl`、`bus/truck`，以及词长和常见度对 Read/Task 的影响。

## 冻结前的人工复核

1. 打开接触图定位，逐张用原分辨率查看 `data/raw/coco/val2017/<file_name>`；在 `coco_review.csv` 将 `decision` 改为 `accept` 或 `reject` 并记录原因。重点排除：自带可读大字、主体不清晰、未标注但同样显眼的物体、敏感或损坏内容。缩略图只能用于初筛。
2. 按 `coco_base_120.provisional.json` 为 144 张暂定图逐张核对四个选项，特别是 `wrong_class`；在审查记录中补充 MCQ 通过状态。任何改变候选或选项后重新生成暂定索引并重审。
3. 检查不同类的覆盖：Formal 至少 30 个细类，每类不超过 6 张；四个主类均有样本；Pilot 与 Formal/Reserve 无共享 image ID；A–D 与误导项位置保持均衡。对同场景、同主体的近重复图再做人工剔除，避免 120 张名义上不同却内容高度重复。
4. 仅在图像与选项复核、下述 Pilot 门槛通过后，把版本化文件复制为 `data/manifests/coco_base_120.json`，写入数据/Prompt/渲染版本及文件哈希，并由成员 1 与成员 2共同确认。此后 C0–C3 的底图与选项不可单方改动。

## 为什么先做小 Pilot，以及怎么做

**需要做。** COCO bbox 只说明标注目标大小，不能保证干净图可以被模型稳定认出，也不能保证新增文字能被读到且不挡住目标。先用 12 张唯一底图做数据与评测仪器的门控，避免 120 张正式集和数千次 API 调用后才发现条件无效。

1. 从暂定 Pilot 的四个组各 3 张进行完整人工核验，固定四选一选项和正确答案。先渲染 C0、C1/C2 的 margin/object、C3 的 margin/object。留出 3–4 张检查 16px 低对比字与 60px 大字。渲染后逐像素检查 C0/C1/C2 的**框外区域**一致，并人工检查字形、裁切、位置；不能只核验 bbox。
2. 先做**零成本数据 Pilot**：人工对 12 张 C0 独立答题，确保没有题目歧义；检查每个 `wrong_class` 在原图中确实不存在。若两名复核者对真值/误导项意见不一致，替换样本或选项。
3. 再做**小型模型 Pilot**：优先 2 个同家族 Instruct 模型（8B/32B），12 张 × 7 个 Task/Read 条件 × 2 模型约 168 次调用；同时测 C3 两种位置的 Task+Read（12 × 4 × 2 = 96 次），共约 264 次。模型配置、prompt、温度和解析器与正式实验一致；记录逐请求原始响应、token、延迟、错误和图像哈希。若预算充足再扩展到计划中的全部 5 模型、660 次请求。16px/60px 梯度检查需要**另加** Read 请求，原计划 660 次并未包含这项门槛。
4. 按计划预设门槛检查：32B C0 准确率 ≥85%；C0 到 C1_object 的准确率下降 ≤10 个百分点；正常 36px Read ≥80%，低对比小字比正常字低至少 15 个百分点；`P(O|¬R) < 0.05`；合法格式率 ≥95%；Thinking 的 `reasoning_content` 与最终 `content` 分离正常。12 张仅用于排故，比例波动很大；例如 1 张就等于 8.3 个百分点，因此门槛触发后应先读逐例日志再决定改数据、渲染或 prompt，不把小样本差异当研究结论。
5. Pilot 通过后冻结 120 Formal；用同一题目和同一图在 C0–C3 做配对比较。不要用 Formal 来反复调图、改门槛或挑选“表现好”的样本。Formal 的最终估计给出分子/分母及图像级配对 bootstrap 置信区间；`P(O|R)` 的分母必须是 Read 成功的样本数，分母过小时报告不稳定，不得只报百分比。

### 需要特别修正的测量风险

- `bbox` 占比不是可见像素占比：遮挡、背景和图片缩放会改变实际读图难度。图内贴字必须记录与主体框的重叠比例，并对 C1/C2 使用相同几何位置。
- C1 的中性词与 C2 的类别词若长度不同，视觉面积和 OCR 难度可能不同；应在渲染日志保存字体大小、文本 bbox 和背景亮度，必要时按长度匹配中性词。
- C3 的三种指令模板与暗号是绑定轮换的；模板效应和暗号效应会混淆。正式实验宜独立轮换或在报告中明确二者不可分。
- `P(R)` 的独立 Read Probe 与 Task Probe 是不同调用；把二者相乘是机制分解的近似，不能把单次 Read 正确当作同一次 Task 内确实阅读的直接证据。建议保留逐图 Read/Task 联表和错误案例。
